# インシデント記録: 古いファイルを push・デプロイした件

- 日付: 2026-10-18
- 重大度: 高(本番に意図と異なる版を公開。機能・データへの被害なし)
- 状態: 解消済み(正しい版を本番へ反映)

## 1. 何が起きたか

ログイン画面の変更(ロゴを最上部へ、ハート+テキスト削除)を「push済み」と報告したが、実際に push・デプロイされたのは **変更前の古いファイル**だった。ユーザーが本番を見て「変わってない」と指摘して発覚。

## 2. 時系列

| コミット / デプロイ | 内容 |
|---|---|
| `33b8a0a` | ハート+テキスト削除(正) |
| `4e5382f` | ロゴ差し替えのつもりが `logo.png` 以外は古い内容(誤) → デプロイ `dpl_9K9E…`(READYだが古い) |
| `5abc95b` | 正しいファイルで再コミット |
| `dpl_7LTQtJwY7UijHDsBLH9vom1PX5PV` | 正しい版。本番エイリアス反映・配信JS/ロゴで確認済み |

## 3. 根本原因

直接原因: 配信用フォルダ(`/mnt/user-data/outputs`)へのコピーが**実行されなかった**。

1. 1つの `bash -c` 内に `pkill -f "next start -p 3113"` と後続の `cp` を同居させた。
2. `pkill -f` は**コマンド文字列自身にもマッチ**するため、自分のシェルを kill(終了コード **144**)。
3. `cp` 以降が未実行のまま、outputs に残っていた**旧ファイル**が配信・commit・push された。

見逃し要因(これが重大):

- 終了コード144を無視して先へ進んだ。
- コピー元・outputs・Mac側の **md5 を比較しなかった**。
- 「`git status` がクリーン」を「内容が最新」と取り違え、`push 済みです` と報告した。
- デプロイ後、**READY状態しか確認せず**、配信されている内容(JSチャンク/画像サイズ)を見なかった。
- 副次的な違和感(ロゴのサイズ表示が前回値と不一致)を調べず放置した。

## 4. 影響

- 約10分間、本番がひとつ前のレイアウト(ハート削除済み・ロゴ下部)を表示。
- 機能障害・データ損失・認証への影響なし。

## 5. 是正

- `cp -f` で再コピー → 全経路で md5 一致を確認 → `5abc95b` を push → デプロイ。
- 配信チャンク `page-cb54656c0d08c653.js` に新レイアウト、`/logo.png` が新サイズであることを確認。

## 6. 再発防止ルール(非自明な制約のみ)

1. **`pkill -f <パターン>` を、そのパターンを含むコマンドと同じ呼び出しに入れない。** 別呼び出しにするか PID 指定で kill。
2. **終了コードが0以外(144含む)なら停止して原因確認。** 続行しない。
3. **commit前に md5 照合**: 作業元 = outputs = Mac側。不一致なら push しない。
4. **「完了」の根拠は内容**: `git status` やデプロイ READY では完了としない。配信HTML/JS/アセットの実体(マーカー文字列またはサイズ)で確認してから報告。
5. 想定外の数値(サイズ等)の食い違いは、その場で原因を潰す。
